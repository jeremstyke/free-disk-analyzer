PurgeCore v1.5.0: Browser Cleanup Fixes

2026

v1.5.0 is a focused bug-fix release for browser cleanup, three real issues found during a code review, none of them dangerous, but all of them made the feature feel less trustworthy than it should.

Fixed: no feedback while scanning or cleaning

Clicking Rescan or Clean selected used to change nothing visible on screen while the work happened in the background, clearing a large browser cache can take a little while, especially since deleted files go to the Recycle Bin rather than being removed outright. Without any indicator, that looked like the app had frozen. There's now a "Scanning..." and a "Cleaning, this can take a while for large caches..." message while each is in progress.

Fixed: could start overlapping scans

Nothing previously stopped a second scan from starting while one was already running, clicking Rescan repeatedly could leave the list in an inconsistent state. The button is now disabled while a scan or clean is already in progress.

Fixed: freed space could be overstated

Chrome and Edge's cache is actually two folders (Cache and Code Cache) shown as one item. If only one of the two could be deleted, for example because the other was locked by a running browser, the app was still reporting the combined size of both as freed. Freed space is now measured from what was actually deleted, not assumed from the original scan.

Fixed: misleading whitelist message

The confirmation dialog said "cookies for N whitelisted domains will be kept" even when no cookie items were selected to begin with, for example when only clearing cache or history. It now only mentions the whitelist when cookies are actually part of what's being cleaned.

None of this changes what the feature does, just how honestly it reports on what happened. If you noticed browser cleanup feeling unreliable before, this release is why.
